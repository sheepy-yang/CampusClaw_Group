## 骨架状态与快速启动

当前版本是第 7 课项目骨架：提供可启动的 Web、API、Worker、MCP、Nginx 和数据依赖，以及规约、工程规则、健康检查、结构化日志与接口契约；**不实现十二项教学业务，也不调用真实模型**。

cp .env.example .env

### 2. 一条命令启动

```bash
docker compose up -d --build
```

启动完成后访问：

- 页面：`http://127.0.0.1:8088/`
- 健康检查：`http://127.0.0.1:8088/health`

`/health` 返回 HTTP 200 且 MySQL、Redis、Qdrant、MinIO、MCP 全部为 `up` 才算启动成功。故障排查使用：

```bash
docker compose ps
docker compose logs --no-log-prefix api mcp worker nginx
```

停止并保留数据卷：

```bash
docker compose down
```

### 3. 提交前验证

填写 `.env` 后执行：

```bash
make verify
```

该命令依次严格校验 OpenSpec、运行两个 Go 模块测试、安装并构建前端、检查依赖漏洞和 Compose 配置。人工项见 [`docs/lesson-07/verification.md`](docs/lesson-07/verification.md)。

## 一、项目题目

**CampusClaw 智能教学全流程扩展——可验证生成、多模态评价与自适应辅导**

## 二、项目定位

本项目面向高校教学场景，在 CampusClaw 平台上构建贯穿课前、课中和课后的智能教学系统。系统将课程知识、教学活动和学生学习数据连接起来，为教师提供内容生产、作业评价和班级分析能力，为学生提供过程化辅导和个性化学习支持。

项目围绕十二项相互衔接的智能教学功能，形成完整教学闭环：

```text
课前备课、虚拟课堂演练与预习
  → 教师命题与发布
  → 学生自适应练习与正式作答
  → 主观题异步批改与作答过程回放
  → 班级讲评与学习诊断
  → 个性化复习
  → 结果反哺后续备课
```

十二项功能均设计为可启用、可停用、可独立验收的技能模块。系统遵循：

> **权限校验 → 获取可信数据 → 模型生成 → 结果校验 → 教师确认 → 发布与审计**

教案、试题、成绩和诊断结论均由教师确认后正式发布。

## 三、主要功能

### 1. 十二项核心智能教学功能

| 核心功能 | 主要能力 | 关键约束与验收条件 |
| --- | --- | --- |
| 智能命题 | 教师选择本班讲义、知识点、题型、难度和题量，由生成与验证两个智能体协作形成试卷、答案、解析及证据链 | 答案通过独立工具校验；引用只能来自本次检索；教师逐题采纳后才能发布；学生提交前看不到答案 |
| 智能备课 | 根据教学目标、本班讲义和近期学习情况生成教学目标、重难点、教学过程、例题、分层练习及板书建议 | 事实性内容必须有讲义依据；教师可逐段修改；未经确认的教案不能发布或进入知识库 |
| 虚拟学生课堂演练 | 教师选定教案后，由不同基础水平和学习风格的虚拟学生智能体模拟提问、误解和课堂回应，生成教学薄弱点与改进建议 | 模拟角色、依据和对话过程可查看；报告明确标注为教学演练；结果只用于修改教案，不评价真实学生 |
| 多模态主观题批改 | 客观题按确定规则判分；主观题和手写作答进入异步队列，完成转写、步骤划分、首错定位、建议分和错因判断 | 学生先确认转写结果；低置信度结果进入教师复核；教师改分后以教师结果为准；模型失败不丢失提交 |
| 作答过程回放与原创性审查 | 周期性保存作答版本，形成可回放的修改时间线，并对同次作业答案和已引用资料进行语义与结构相似性分析 | 只保存明确作答时段的内容快照，不记录键盘行为；系统展示相似片段和来源证据，由教师作出最终判断 |
| 班级讲评 | 汇总一次作业的高频错题、共性错因和典型解法，生成讲评提纲、例题与补救题 | 有效提交少于 5 人时不调用模型；输入模型前去除姓名；全班统计和个体对比仅教师可见 |
| 学习诊断 | 根据真实作业、练习、求助和辅导记录建立带时间顺序的学习证据，分析知识点掌握、反复错误和改进趋势 | 作答少于 3 次时只显示「样本不足」；每项诊断列出证据事件；个人报告经教师确认后才向学生开放 |
| 个性化复习路径 | 根据学生近两周错题、薄弱知识点和任务完成情况，动态生成并调整 3～5 步阅读、例题、练习和自测计划 | 没有错题或有效记录时不调用模型；路径只对学生本人和本班教师可见；自测不计入正式成绩 |
| 自适应练习闯关 | 根据目标知识点和学生每题作答情况，实时调整下一题的难度、题型与前置知识范围，形成 5～10 题的个性化练习会话 | 动态题目经答案与引用校验后展示；状态转移规则可解释；练习结果用于学习建议，不计入正式成绩 |
| 智能预习单 | 根据讲义内容和班级前序知识掌握情况，生成知识卡片、思考题、易错提示和客观自测 | 有效知识卡片少于 3 张时不保存；内容需标注讲义来源；教师确认后推送给学生 |
| 追问式辅导 | 针对已判错题目维护学生学习状态，并根据每轮回答动态选择追问策略，引导学生发现错误并修正思路 | 连续两轮回答击中要点、达到轮次上限或学生明确要求讲解后，展示完整解析 |
| 课堂回答聚类 | 收集课堂短文本回答，识别表层答案背后的概念差异与典型误区，归纳为最多 4 类并生成追问建议 | 有效回答少于 5 人时不调用模型；发送给模型的数据不含姓名；聚类结果不作为成绩 |

### 2. 重点创新功能

#### 虚拟学生课堂演练

1. 教师选择已确认教案，设置课程阶段、模拟轮数和希望检验的教学目标；
2. 系统创建基础较强、一般和薄弱等不同虚拟学生角色，并公开每个角色的知识边界；
3. 虚拟学生围绕教案内容分别提出问题、给出回答或暴露典型误解，教学智能体模拟教师应答；
4. 评价验证智能体检查对话与讲义、教案的一致性，标记缺乏依据的内容；
5. 系统生成课堂风险时间线、可能卡点、备用解释和教案修改建议；
6. 教师采纳建议后可再次演练，并对比修改前后的问题覆盖情况。

#### 自适应练习闯关

1. 学生选择复习路径中的知识点，系统从中等难度且已验证的题目开始；
2. 每次作答后更新「掌握证据、错误类型、连续正确次数和已使用提示」等会话状态；
3. 回答正确且解释充分时提升难度，出现概念性错误时转入前置知识题，计算失误时提供同层变式题；
4. 动态生成的题目先完成引用、答案和难度验证，再展示给学生；
5. 达到掌握条件、题量上限或学生主动结束时，生成练习报告并更新复习路径。

#### 作答过程回放与原创性审查

1. 作业编辑器按固定时间间隔和主动保存动作记录内容快照，图片提交记录文件摘要和版本；
2. 学生提交前可以回看版本、补充引用来源并填写 AI 工具使用说明；
3. 提交后，系统比较同次作业答案、学生自己的历史版本及教师提供的参考资料；
4. 教师端以并排方式展示相似片段、相似度、可能来源和修改时间线；
5. AI 只归纳需要关注的证据，不直接生成学术不端结论，教师完成复核与处置。

### 3. 教师端与学生端

**教师可以：**

- 按班级启用或停用十二项核心技能；
- 发起备课、虚拟课堂演练、命题、讲评、诊断和课堂聚类任务；
- 审核、修改、采纳或驳回 AI 结果；
- 查看异步任务状态、MCP 调用、模型版本、失败原因和审计记录；
- 回放作答版本并根据相似片段的来源证据完成人工审查；
- 修改 AI 建议分，并保留修改前后结果和说明。

**学生可以：**

- 查看教师确认并发布的试卷、预习单和复习路径；
- 参加动态调整难度与知识范围的自适应练习；
- 提交文本答案、附件或手写作答图片；
- 查看本人作答版本、补充引用来源和填写 AI 工具使用说明；
- 查看本人最终批改结果、错因和追问式辅导；
- 参加教师发起的课堂短文本互动；
- 只能访问本人和本班允许访问的数据，不能使用教师专属功能。

### 4. 内容生命周期与版本管理

- 试题经历「草稿 → 自动校验 → 教师审核 → 已发布 → 已归档」状态；
- 教案、预习单、讲评和诊断经历「生成中 → 待确认 → 已确认/已驳回 → 已发布」状态；
- 课堂演练保留模拟角色、轮次、对话和教案修改前后的对比报告；
- 自适应练习保存每题难度、知识点、状态转移原因和会话结束条件；
- 作答过程保存版本快照、引用声明和原创性审查证据；
- 作业发布后冻结题干、标准答案、评分规则和引用切片，后续重建知识索引不能改变已发布内容；
- 提示词、技能和模型配置记录版本，历史结果能够追溯到生成时使用的版本；
- 删除或停用技能后，不删除既有结果和审计记录。

## 四、技术方案

### 1. 总体架构

```text
浏览器
  │
React + TypeScript（教师端 / 学生端）
  │
Nginx
  │
Go API
  ├─ 平台服务：认证、班级隔离、讲义检索、助手、作业与审计
  ├─ 教学应用：十二项技能编排、内容审核、版本与发布状态
  ├─ 智能服务：模型网关、MCP 主机、安全检查与 SSE
  │
  ├─ MySQL：业务数据、演练会话、作答版本、批改结果、诊断与审计
  ├─ Qdrant：讲义切片、试题、错题和匿名作答向量
  ├─ Redis + Worker：课堂演练、批改、相似性分析、讲评、诊断和命题
  ├─ MinIO：手写作答与附件对象
  ├─ MCP Server：受鉴权和审计约束的教学工具
  └─ LLM / Embedding Gateway：文本、多模态与向量模型
```

浏览器只访问 Nginx。MySQL、Qdrant、Redis、MinIO、MCP 服务及模型密钥均不直接暴露给浏览器。

### 2. 智能体协作与可验证任务链路

系统设置统一编排智能体、教学内容智能体、虚拟学生智能体、评价验证智能体和个性化辅导智能体。统一编排智能体根据任务目标生成有限步骤计划，专业智能体通过结构化任务状态协作，评价验证智能体独立检查生成结果，关键节点由教师完成确认。

十二项功能共用以下任务链路：

1. 服务端验证 Token、角色、班级和资源归属；
2. 编排智能体依据技能模板分解任务并建立可恢复的状态记录；
3. 专业智能体读取当前班级讲义、作业或当前用户自己的错题；
4. 服务端依据技能白名单控制知识库检索和 MCP 工具的执行范围；
5. 专业智能体按照 JSON Schema 返回结构化结果和置信度；
6. 评价验证智能体检查字段、引用、答案、人数门槛和内容安全；
7. 验证未通过时执行有限次数的定向重试，仍未通过则转入教师复核；
8. 生成结果进入教师审核或学生确认流程，正式成绩以教师确认结果为准；
9. 保存任务计划、状态迁移、模型、提示词、技能、引用、工具调用、耗时和人工修改记录。

对于依赖讲义的命题、备课和预习功能，系统在取得可靠检索依据后生成内容。课堂聚类等功能以用户提交文本为可追溯数据来源，并清晰标注相应依据。

### 3. 可验证命题与批改

- 选择题和填空题优先使用确定性规则判分，不调用大模型；
- 数学表达式和方程调用 MCP 工具进行化简、求解和等价性验证；
- 主观题由模型给出结构化评分项、建议分、错因和依据，教师拥有最终决定权；
- 手写图片先由多模态模型转写为带 LaTeX 的步骤，学生确认后再进入批改；
- 可形式化的步骤由符号工具验证，其他步骤由模型结合评分规则判断；
- 低置信度、工具与模型结论冲突或依据不足时，任务自动标记为「待教师复核」；
- 自适应练习中的动态题目经过与正式命题相同的答案和引用校验后才进入当前会话；
- 原创性审查只提供相似片段、来源与版本变化等证据，不直接改变成绩或生成纪律结论。

### 4. MCP 工具设计

同仓实现 `mcp-teaching-tools` 服务，由 Docker Compose 一并启动，至少提供：

| 工具 | 说明 |
| --- | --- |
| `formula_verify` | 验证数学表达式、方程答案和步骤等价性 |
| `assignment_stats` | 按权限返回本班作业的匿名聚合统计，仅教师可调用 |
| `student_mistakes` | 返回当前学生本人的错题摘要；教师调用时必须限定本班 |

MCP 服务实现 `initialize`、`tools/list` 和 `tools/call`，使用 Bearer Token 鉴权。教师在 CampusClaw 中完成服务器登记、连接、工具发现和断开；技能只能绑定已连接、已发现且属于本班的工具。调用结果作为数据进入模型上下文，不作为系统指令。所有调用记录工具、用户、班级、状态和时间；工具失败只影响当前工具步骤，不中断其他可继续执行的主路径。

### 5. 异步任务与数据一致性

- 虚拟课堂演练、主观题批改、手写识别、相似性分析、班级讲评、学习诊断和批量命题通过 Redis 队列执行；
- API 先保存用户提交和任务记录，再投递任务，模型故障时保留数据并支持任务重试；
- Worker 使用幂等键避免重复生成、重复评分或重复发布；
- 任务状态包含排队、处理中、待确认、成功和失败，失败任务可安全重试；
- 教师修改分数、发布内容或驳回结果使用数据库事务并记录审计。

### 6. 权限、安全与隐私

- 班级和角色只从服务端认证上下文取得，不采信客户端提交值；
- 学生调用教师专属技能返回 403，跨班资源与不存在资源采用一致的 404；
- 模型 API Key、MCP Token、数据库口令和对象存储密钥只保存在服务端环境变量；
- 班级讲评和课堂聚类发送模型前去除姓名等直接身份信息；
- 手写图片使用短期授权地址访问，不公开对象存储路径；
- 作答过程只记录定时快照和主动保存版本，不采集逐键输入；学生只能查看自己的作答过程；
- 对讲义、学生输入和 MCP 输出执行提示注入与内容安全检查；
- 页面、接口、异步任务和工具调用均产生可查询审计记录。

### 7. 接口、测试与部署
